# Подключение физической Tuya Wi-Fi-розетки через Smart Life

Используйте существующий проект. Для подключения не требуется перепрошивка розетки, локальный ключ или повторное сопряжение уже работающего устройства. API-ключи остаются в `.env` на сервере.

Проверьте совместимость со своей розеткой: получите её Device ID, прочитайте схему и показания, затем выполните отдельные тесты ON и OFF с физической проверкой результата.

## 1. Проверьте Smart Life

1. Откройте **Smart Life** на телефоне под тем аккаунтом, куда добавлена ваша розетка.
2. Розетка должна отображаться **Online**. Если она ещё не добавлена, выполните сопряжение по инструкции производителя. Требование Wi-Fi 2.4 GHz уточните для конкретной модели.
3. Посмотрите регион аккаунта: **Me / Я → Settings / Настройки → Account and Security / Аккаунт и безопасность → Region / Регион**. Названия могут различаться по версии приложения.
4. При проверке питания используйте нагрузку, которую допустимо включать/выключать сейчас. Сайт не будет самостоятельно тестировать ON/OFF в ходе диагностики.

## 2. Создайте проект Tuya Cloud

1. Зарегистрируйтесь или войдите на [platform.tuya.com](https://platform.tuya.com/).
2. Откройте **Cloud → Development → Create Cloud Project**.
3. Укажите имя, например `Tuya Power Monitor`.
4. Выберите направление/тип разработки **Smart Home / Smart Home PaaS**. Не выбирайте произвольный Custom Development проект: у него другая модель привязки устройств.
5. Выберите **Data Center**, обслуживающий регион аккаунта Smart Life. Регион аккаунта и дата-центр cloud-проекта должны соответствовать друг другу. Не определяйте регион по VPN или местоположению компьютера.
6. Проверьте доступный план **IoT Core / Cloud Development** и лимиты. Приложение не обещает бесплатность или бессрочный доступ: актуальные условия показаны в вашем кабинете Tuya.

Официальный [порядок работы со Smart Home PaaS](https://developer.tuya.com/en/docs/iot/migrate-from-an-older-version?id=Kamee9wtbd00b) описывает соответствующий тип проекта и привязку приложения; сами шаги установки Home Assistant из той статьи этому проекту не нужны.

## 3. Авторизуйте API

В проекте откройте **Service API** и проверьте, что проект имеет доступ к операциям:

- Authorization / Authorization Token Management — получение токена.
- Smart Home Basic Service / IoT Core — разрешённые устройства, данные устройства, схема функций, status и commands.

Названия пакетов зависят от кабинета и подписки. Важен доступ к используемым адресам API:

```text
GET  /v1.0/token?grant_type=1
GET  /v1.0/users/{uid}/devices
GET  /v1.0/devices/{device_id}
GET  /v1.0/iot-03/devices/{device_id}/specification
GET  /v1.0/iot-03/devices/{device_id}/status
POST /v1.0/iot-03/devices/{device_id}/commands
```

Для API-проверки в Tuya API Explorer используйте только чтение, пока сами не готовы переключать нагрузку. Приложение покажет код ошибки и конкретную подсказку, если API не авторизован или подписка истекла.

## 4. Привяжите аккаунт Smart Life

1. Откройте cloud-проект → **Devices → Link Tuya App Account → Add App Account**.
2. Убедитесь, что сверху выбран правильный дата-центр.
3. Отсканируйте появившийся QR-код сканером в **Smart Life**.
4. Подтвердите связь с проектом на телефоне.
5. В **Devices → All Devices** должна появиться ваша физическая розетка. Если список пуст, проверьте аккаунт Smart Life, регион и разрешения привязки.
6. Скопируйте **UID** из строки привязанного аккаунта. Это не ваш email и не ID cloud-проекта.
7. Найдите **Device ID** вашей розетки в All Devices. Не используйте вместо него Product ID, MAC или виртуальное устройство.

См. официальный [Link Tuya App Account → Add App Account](https://developer.tuya.com/en/docs/iot/space-device-control-practice?id=Kcoxmvivehrn0). В этой статье есть также примеры виртуальных устройств; для вашей задачи виртуальное устройство добавлять не нужно.

## 5. Заполните .env на компьютере

1. Остановите сервер **Ctrl+C** в окне его запуска. Если он запущен внутри Codex, попросите остановить/перезапустить текущий экземпляр.
2. В папке `tuya-power-monitor` откройте файл **`.env`**. Если его ещё нет, скопируйте **`.env.example`** и переименуйте копию точно в `.env`, не `.env.txt`.
3. В cloud-проекте **Overview → Authorization Key** скопируйте **Access ID / Client ID** и **Access Secret / Client Secret**. Это ключи cloud-проекта, а не пароль Smart Life.
4. Заполните локальный файл:

```dotenv
APP_PASSWORD=отдельный_надёжный_пароль_для_сайта
TUYA_REGION=eu
TUYA_CLIENT_ID=Access_ID_проекта
TUYA_CLIENT_SECRET=Access_Secret_проекта
TUYA_UID=UID_аккаунта_Smart_Life
TUYA_POLL_SECONDS=15
COOKIE_SECURE=false
ALLOWED_ORIGINS=http://127.0.0.1:8000,http://localhost:8000
```

`APP_PASSWORD` — отдельный пароль панели. Не используйте вместо него Access Secret или пароль Smart Life. **Не отправляйте Access Secret, пароль или файл .env в чат.**

Значения региона:

| TUYA_REGION | Data Center |
|---|---|
| `eu` | Central Europe |
| `we` | Western Europe |
| `us` | Western America |
| `ea` | Eastern America |
| `cn` | China |
| `in` | India |
| `sg` | Singapore |

Значение `eu` в шаблоне — пример. Выберите реальный дата-центр своего проекта. Если используете готовый Device ID вместо списка аккаунта, оставьте `TUYA_UID=` пустым и задайте `TUYA_DEVICE_IDS=ваш_device_id`. Доступ проекта к этому устройству всё равно необходим.

`SESSION_SECRET` можно задать постоянной случайной строкой длиной не менее 32 символов. При пустом значении новый секрет сессий создаётся на каждом запуске; потребуется вход заново, а Connection Setup попросит повторить диагностику и не будет доверять прежним подтверждениям тестов.

## 6. Выполните диагностику без переключения

1. Запустите **Start.cmd**. Откройте [панель подключения](http://127.0.0.1:8000/#connection).
2. Войдите с заданным **APP_PASSWORD**.
3. В меню **Connection Setup** нажмите **Проверить подключение**.
4. Проверьте результаты: настройки → токен/Cloud → список устройств → схема и status.
5. Выберите вашу розетку и сверьте **Device ID** с Tuya Platform.
6. Посмотрите реальные функции, исходные DP, типы, `scale`, `unit` и нормализованные показания. `—` означает отсутствие доступного показания; это не нулевое потребление.

Альтернатива через консоль: **Diagnose.cmd** либо

```powershell
.\.venv\Scripts\python.exe -m backend.diagnose
```

Консольная проверка **не запускает планировщик, не посылает команды реле и не изменяет БД**. Код возврата 1 означает, что подключение/устройство пока не готово; JSON содержит причины. В JSON нет ключей или токена, но Device ID и сведения о ваших устройствах могут присутствовать — не публикуйте отчёт без необходимости.

## 7. Проверьте соответствие Data Points

Обычные названия — `switch_1`, `cur_power`, `cur_voltage`, `cur_current`, `add_ele`. Приложение назначает их только если они действительно присутствуют в схеме и подходят по типу/единице.

Если у вашей модели, например, `relay_main` вместо `switch_1`:

1. В Connection Setup разверните **Сопоставление модели · нестандартные Data Points**.
2. Выберите нужную Boolean-функцию для реле из реальной схемы. Не выбирайте индикатор/подсветку, если это не силовое реле вашей модели.
3. Выберите энергетические DP, если они есть. Неподдерживаемые показатели оставьте неназначенными.
4. Нажмите **Сохранить и перечитать состояние**. Сохранение и повторная диагностика не переключают реле и доступны до активации реального режима.

`scale=1` означает деление исходного числа на 10. Например, `cur_voltage=2301`, `scale=1`, `unit=V` → 230.1 В. Ток mA преобразуется в A, Wh — в kWh. У некоторых моделей сложный raw/binary DP, который не декодируется этими правилами: он не будет выдан за корректные ватты. Потребуется отдельный документированный декодер модели.

`add_ele` может иметь семантику интервального расхода, а не накопительного счётчика. Поэтому он называется **энергетический DP**, а аналитика отдельно использует интеграл реальной мощности и отмечает расчётный характер энергии.

## 8. Активируйте розетку

1. Когда доступны Online, Boolean-команда и Boolean-значение status, нажмите **Использовать эту розетку**.
2. Backend ещё раз проверит доступ, схему и состояние, переключит панель в **Tuya** и приостановит сохранённые реальные автоматизации.
3. Само реле при активации **не переключается**. Прямой переход из демо в Tuya через обычные настройки запрещён, чтобы старый таймер не выключил нагрузку при подключении.

## 9. Отдельно подтвердите ON и OFF

1. В блоке **Проверка ON и OFF** нажмите **Подтвердить тест ON**.
2. В диалоге сверьте имя и Device ID. Нажмите **Я подтверждаю ON**, только когда подача питания допустима.
3. Backend отправит команду и прочитает status до трёх раз. Успех появится только при ответе API и точном Boolean-значении `true` у выбранного реле.
4. Убедитесь, что **физическая розетка действительно включилась** — по подключённой безопасной нагрузке, индикатору и Smart Life.
5. Отдельно нажмите **Подтвердить тест OFF → Я подтверждаю OFF**, когда выключение допустимо. Backend проверит Boolean `false`.
6. Убедитесь, что физическое питание выключено. Отметки и время облачного подтверждения сохранятся в Connection Setup.

При сообщении **«Состояние реле не подтверждено»** команда могла физически выполниться, но Cloud не подтвердил результат вовремя. Приложение не объявляет успех. Сначала проверьте Smart Life и состояние нагрузки; не повторяйте переключение вслепую.

Последующие кнопки питания Dashboard/Devices также ждут подтверждённого status. Записи успешных автоматических действий создаются только после такой же проверки.

## 10. Реальная энергия и зарядка

Если модель предоставляет мощность, подключите допустимую нагрузку и проверьте **Live Monitoring**. В реальном режиме показания приходят только от Tuya. Модель без мощности управляется как реле; зарядные сеансы и энергия не подделываются.

В Settings настройте тариф в тенге, порог начала и **подтверждение начала** (по умолчанию 5 секунд), порог конца и выдержку завершения (по умолчанию 30 секунд). Для Tuya опроса 15 секунд подтверждение наступает на первом подходящем опросе после выдержки. Короткие всплески между опросами физически могут остаться незамеченными — приложение не обещает точность непрерывного прибора.

Сеансы, средняя/пиковая мощность, Wh/kWh, стоимость, графики и CSV доступны по фактическим наблюдениям. Зарядный сеанс не равен полному циклу батареи; процент аккумулятора недоступен без другого источника.

После ручного теста создайте или включите нужные реальные правила в Automation. Они выполняются при закрытом браузере, пока запущен сервер и доступен Tuya Cloud. Отменяются переключателем правила или удалением. Журнал действий — значок колокольчика. Не включайте неизвестные старые правила, не проверив их параметры.

## 11. Телефон в той же Wi-Fi-сети

1. Подключите компьютер и телефон к одной доверенной Wi-Fi-сети.
2. Задайте APP_PASSWORD в `.env`. Для локального HTTP нужен COOKIE_SECURE=false.
3. Остановите сервер Start.cmd и запустите **Network.cmd**.
4. Откройте на телефоне адрес, показанный в окне после **Phone URL**, и войдите с паролем панели.

Network.cmd использует `scripts/network.py`: автоматически определяет приватный IPv4 и разрешает его точный origin на время работы сервера. Файл `.env` не меняется. Если Wi-Fi изменится, заново запустите Network.cmd и используйте новый адрес.

Если Windows спросит о доступе, разрешайте Python только в доверенной домашней сети. Гостевая сеть может изолировать устройства друг от друга. Скрипт не меняет брандмауэр и маршрутизатор. Адрес 127.0.0.1 на телефоне означает сам телефон и не подходит для связи с компьютером.

Управление адаптировано под Android и iPhone: внизу доступны быстрые разделы, остальные находятся в меню «Ещё». Подробности — [MOBILE.md](MOBILE.md).

Это LAN-доступ, не публикация в интернете. Сервер должен оставаться включённым.

## 12. Доступ через интернет

Для доступа из мобильной сети нужен постоянно работающий сервер с публичным DNS-доменом и HTTPS, например VPS. Компьютер или телефон с сайтом не обязан находиться в сети розетки: сам backend связывается с Tuya Cloud.

Подготовленный вариант — **compose.internet.yaml + Caddy**:

1. На сервере установите Docker/Compose и скопируйте исходники проекта без локального `.env` в публичные репозитории.
2. Настройте DNS A/AAAA вашего домена на IP сервера. Укажите только реально работающие IPv4/IPv6 записи.
3. На сервере заполните `.env`: пароль панели, Tuya-ключи, UID/Device ID, регион и

```dotenv
MONITOR_DOMAIN=power.ваш-домен.example
COOKIE_SECURE=true
```

Используйте настоящий домен вместо примера. `SESSION_SECRET` задайте постоянной случайной строкой.

4. Запустите **один** экземпляр:

```sh
docker compose -f compose.internet.yaml up --build -d
docker compose -f compose.internet.yaml logs -f
```

5. Порты 80/443 сервера должны быть доступны Caddy. Backend-порт 8000 в этом compose-файле не публикуется наружу. Caddy получит HTTPS-сертификат для вашего домена и проксирует REST/WebSocket.
6. Откройте `https://ваш-домен/#connection`, войдите и повторите диагностику с сервера. Интернет-режим сам устанавливает `ALLOWED_ORIGINS=https://MONITOR_DOMAIN`.
7. Не запускайте параллельно ещё один backend, управляющий той же розеткой и правилами. Если переносите историю, перенесите SQLite при остановленном сервере или выполните отдельную миграцию.

См. [Caddy HTTPS quick start](https://caddyserver.com/docs/quick-starts/https) и [reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy). Развёртывание на вашем сервере не выполнялось: домен и хостинг не предоставлены. Docker/HTTPS-конфигурация подготовлена; фактическую выдачу сертификата необходимо проверить на сервере.

## Ошибки подключения

| Ошибка | Что проверить |
|---|---|
| Не все параметры заданы | .env рядом со Start.cmd; APP_PASSWORD, TUYA_CLIENT_ID/SECRET и UID либо DEVICE_IDS; перезапуск backend |
| `1004` | Правильные Access ID/Secret одного проекта, TUYA_REGION и часы системы |
| `1106` | Привязка именно нужного Smart Life аккаунта по QR, правильные UID/Device ID и дата-центр |
| `28841105` | Проекту не авторизован нужный API в Service API |
| `28841101` / `28841106` | Не подключён необходимый API-пакет |
| `28841102` / `28841002` | Срок API-подписки или плана cloud-проекта |
| `28841104` / `28841004` | Квота API или cloud-проекта; увеличьте интервал опроса, проверьте лимиты |
| Online в списке, status недоступен | Права на status, действующий план, актуальное состояние Smart Life |
| Нет Boolean-реле | Выберите правильную функцию из схемы; модель или её cloud-инструкция может не поддерживаться этим API |
| ON/OFF не подтверждено | Команда могла исполниться; прочитайте состояние в Smart Life, проверьте выбранный код, не повторяйте вслепую |
| Нет энергетики | Наличие реальных power/current/voltage DP, их type/scale/unit; модель может быть без энергомониторинга |
| Нельзя войти по локальному HTTP | COOKIE_SECURE=false; на публичном HTTPS — true |
| Origin запрещён | Точный URL с протоколом и портом в ALLOWED_ORIGINS, затем перезапуск |

Коды и действия сверены с [официальными Tuya Global Error Codes](https://developer.tuya.com/en/docs/iot/error-code?id=K989ruxx88swc). Публичные сообщения не содержат исходный ответ Tuya с потенциальными секретами.
