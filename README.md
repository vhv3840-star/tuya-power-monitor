# TUYA POWER MONITOR

Локальная панель управления умными розетками: React + TypeScript + Vite, Tailwind CSS, Framer Motion, Recharts, Lucide; Python FastAPI, WebSocket и SQLAlchemy/SQLite. В репозитории находятся исходники основного сайта с бело-синим адаптивным интерфейсом. Сборка `dist/` создаётся при первом запуске; личные настройки, ключи и история устройств не включены.

## Запуск Windows

1. Скачайте репозиторий через **Code → Download ZIP** и распакуйте его либо клонируйте через Git. Установите **Node.js 20.19+** (или 22 LTS) с [nodejs.org](https://nodejs.org/) и **Python 3.11+** с [python.org](https://www.python.org/downloads/), отметив **Add python.exe to PATH**. На проверенной машине использован Python 3.12.
2. Дважды нажмите **`Start.cmd`**. Первый запуск создаст `.venv`, установит зависимости из `backend/requirements-lock.txt` и скопирует `.env.example` в `.env`. Затем он установит зависимости frontend и создаст `dist/`. Для первой установки нужен интернет.
3. Откроется [http://127.0.0.1:8000](http://127.0.0.1:8000). По умолчанию работает деморежим без пароля: две розетки, 30 дней синтетической истории, настоящий backend и база данных.
4. Оставьте окно сервера открытым. **Ctrl+C** останавливает сервер и автоматизации. Закрытие страницы не останавливает сервер. Сон/выключение компьютера останавливают выполнение правил.

После первой сборки для работы backend достаточно Python. После изменения frontend запустите `Rebuild.cmd`. После пересборки перезапустите сервер и обновите страницу. Код запуска также поддерживает pnpm и комплект Node/pnpm в Codex.

Командная строка:

```powershell
python scripts/launch.py
# Только подготовка и проверка окружения:
python scripts/launch.py --check
# Без автоматического открытия браузера:
python scripts/launch.py --no-browser
```

Сервер слушает только loopback. Если порт 8000 занят другим приложением, запуск сообщает об этом. Повторный запуск рядом с уже работающим экземпляром открывает его без создания второго планировщика.

## Проверка деморежима

- На главной странице кнопка питания включает и выключает выбранную розетку через API.
- В **Мониторинг → Демо-лаборатория** нажмите «Начать зарядку». Мощность плавно снижается за 3 минуты, затем устанавливается ниже порога завершения. После выдержки сеанс сохраняется в истории.
- «Низкая мощность» ускоряет переход к завершающей фазе; выдержка всё равно соблюдается.
- «Потерять связь» проверяет поведение офлайн. Последние значения остаются видимыми, интегрирование приостанавливается, отсчёт низкой мощности сбрасывается. «Восстановить связь» продолжает опрос.
- В **Автоматизация** создайте таймер на 1 минуту, закройте страницу, затем вернитесь: реле выключится, правило станет неактивным, выполнение попадёт в журнал событий.
- В истории нажмите на дату сеанса, чтобы открыть его график. CSV открывается в Excel (UTF-8 BOM).

Все синтетические данные имеют `mode=demo`. Реальные данные — `mode=tuya`. Фильтрация действует в истории, аналитике, CSV, правилах и журнале. Приложение никогда не подменяет недоступные данные Tuya симулятором.

## Подключение настоящей розетки Tuya / Smart Life

Откройте **Подключение** в меню или [http://127.0.0.1:8000/#connection](http://127.0.0.1:8000/#connection). Это восьмой раздел приложения: пошаговая инструкция, безопасная диагностика без команд, реальные Device ID, таблица DP и отдельные подтверждения тестов ON/OFF.

1. В Tuya Platform создайте Smart Home PaaS cloud-проект и выберите дата-центр своего аккаунта Smart Life.
2. Предоставьте проекту доступ к необходимым API и привяжите Smart Life через Devices → Link Tuya App Account → Add App Account / QR.
3. В локальном `.env` задайте APP_PASSWORD, TUYA_CLIENT_ID, TUYA_CLIENT_SECRET, TUYA_REGION и TUYA_UID либо TUYA_DEVICE_IDS. Не отправляйте секреты в чат.
4. Перезапустите backend, войдите, нажмите **Проверить подключение**. Для нестандартных кодов выполните сопоставление прямо на этой странице.
5. Нажмите **Использовать эту розетку**. Старые реальные правила приостанавливаются, реле не переключается. Обычные Settings не позволяют обойти этот переход.
6. Только после собственных отдельных подтверждений выполните тест ON, затем OFF. API acknowledgment и повторный Boolean status должны совпасть; осмотрите физическую розетку самостоятельно.

**Полная пошаговая инструкция, ошибки, телефон в LAN и HTTPS через интернет: [CONNECTION_GUIDE.md](CONNECTION_GUIDE.md).** Диагностический инструмент без планировщика и изменений БД — `Diagnose.cmd` / `python -m backend.diagnose`.

Все реальные команды, в том числе автоматизации, ожидают подтверждения status до записи успеха. Если подтверждения нет, команда могла выполниться физически, и приложение явно сообщает неопределённый результат.

Совместимость и набор показаний зависят от модели розетки, её Data Points и доступности Tuya Cloud. После настройки проверьте чтение показаний и физическое переключение на собственном устройстве. Демо сохранено как отдельный, явно обозначенный режим и никогда не подменяет Tuya.

## Измерения и расчёты

- Мощность, напряжение и ток в Tuya-режиме — доступные показания устройства, полученные опросом Cloud API. Это не непрерывный поток физического датчика: WebSocket доставляет последние данные в браузер каждые 2 секунды.
- Энергия в аналитике и сеансах — **расчётный интеграл мощности методом трапеций**. Интервалы без показаний и промежутки длиннее `max(90 секунд, 3 × интервал опроса)` не интегрируются. График отмечает пропуски разрывами.
- Отдельный **счётчик устройства** в Live Monitoring показывается, только если розетка предоставляет его и настроено сопоставление. Семантику накопительного счётчика/интервального расхода необходимо сверять с моделью. Он не подмешивается в интеграл мощности.
- Сеанс начинается после подтверждения мощности ≥ порога начала на протяжении start_hold_s (по умолчанию 5 секунд), завершается после показаний ≤ порога конца на протяжении всей выдержки. Восстановление мощности обнуляет выдержку. Потеря связи также обнуляет её. Активный сеанс при смене режима или перезапуске отмечается **«Прерван»**, без предположений о данных во время простоя.
- Сеанс зарядки **не равен полному циклу батареи**. Процент аккумулятора, состояние здоровья и полные циклы недоступны без отдельного источника. Система их не генерирует.
- Стоимость = расчётные кВт·ч × текущий тариф в тенге. Изменение тарифа пересчитывает показанную стоимость всей истории; это не тарифный биллинг с датами действия ставок.
- Периоды 24 часа, 7 и 30 дней скользящие. Сравнение — с непосредственно предшествующим периодом той же длины. График энергии агрегируется по часовым/суточным интервалам, подписи — в выбранном IANA timezone.

## Серверные автоматизации

| Правило | Поведение |
|---|---|
| Таймер | Однократно выключает через N минут от создания/повторного включения правила; после выполнения отключается. Просроченный таймер выполняется после восстановления доступности устройства. |
| Низкая мощность | Выключает после непрерывной последовательности низких показаний на протяжении выдержки. Нужен подтверждающий опрос; одно устаревшее показание не завершает выдержку. После срабатывания правило отключается. |
| Расписание | Ежедневно отправляет ON и OFF в заданные минуты в выбранном часовом поясе. Если сервер/устройство недоступны всю эту минуту, событие пропускается до следующего дня. |
| Ночной режим | Постоянно поддерживает ON внутри временного окна и OFF вне его, включая окно через полночь; применяется также после перезапуска. Ручное переключение может быть переопределено. |
| Лимит зарядки | Выключает спустя N минут после обнаруженного начала сеанса. Нужны мощность и активный сеанс. На каждый сеанс выполняется один раз. |

Правила проверяются сервером примерно раз в секунду между опросами. Cloud-запросы могут увеличивать задержку исполнения; это приложение для бытового мониторинга, не система аварийного отключения. При офлайн-статусе команды не выдаются за выполненные. Правила хранятся в БД, отсчёт низкой мощности намеренно сбрасывается при перезапуске.

Для одной розетки избегайте противоречащих правил. Обработка — от новых к старым; конфликтующие действия могут переопределять друг друга. Работает **ровно один backend worker / один экземпляр приложения для одной базы** — несколько экземпляров будут дублировать автоматизации. Уведомления показываются внутри открытого приложения; при закрытой странице события сохраняются в журнале. Push/email/SMS не подключены.

## Разработка и тестирование

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-lock.txt
.\.venv\Scripts\python.exe -m pytest -q
npm install
npm run build
# или pnpm install --frozen-lockfile; pnpm run build

# Backend:
.\.venv\Scripts\python.exe -m uvicorn backend.main:create_app --factory --host 127.0.0.1 --port 8000
# Во втором терминале frontend dev server с proxy для /api, /auth, /ws:
npm run dev
```

Dev URL — [http://127.0.0.1:5173](http://127.0.0.1:5173). Для Linux/macOS замените `.venv\Scripts\python.exe` на `.venv/bin/python`. В production FastAPI раздаёт `dist/`, отдельный Node-сервер не нужен.

Структура:

```text
backend/
  config.py          # .env, только backend
  domain.py          # детектор сеансов и интеграция
  providers.py       # подпись, токены, Tuya HTTP, capabilities
  storage.py         # SQLAlchemy models
  engine.py          # polling, simulator, rules, journal
  analytics.py       # агрегация и представление данных
  schemas.py         # валидация входных данных
  main.py            # REST, auth, WebSocket, static files
  diagnostics.py     # схема/status, безопасная активация, отчёт
  diagnose.py        # CLI без команд/планировщика/изменений БД
  tests/             # domain, API, provider regression tests
src/
  pages/             # восемь страниц, включая Connection Setup
  components.tsx     # графики и общий UI
  hooks.ts, api.ts   # WebSocket reconnect и API
  App.tsx, style.css
scripts/             # Windows/local bootstrap, rebuild, production entrypoint
dist/                # создаётся при сборке, не хранится в Git
data/                # runtime SQLite, создаётся автоматически
```

REST: `GET /api/state`, `GET /api/analytics`, `GET /api/history`, `GET /api/history/{id}/samples`, `GET /api/export`, `POST /api/devices/{id}/relay`, `POST /api/devices/discover`, `PUT /api/devices/{id}/mapping`, `PUT /api/settings`, `GET/POST /api/rules`, `PATCH/DELETE /api/rules/{id}`. Изменяющие запросы требуют `X-Requested-With: TuyaMonitor`; при установленном пароле — cookie сессии после `POST /auth/login`. WebSocket: `/ws`.

## На телефоне

Запустите `Network.cmd` и откройте показанный адрес на телефоне в той же Wi-Fi-сети. Пароль приложения обязателен. Внизу экрана доступны быстрые разделы, а полное меню открывается кнопкой «Ещё». Подробности — [MOBILE.md](MOBILE.md).

## Развёртывание на сервере

1. Заполните `.env`, обязательно задайте **APP_PASSWORD**. Укажите свой HTTPS origin в **ALLOWED_ORIGINS**, выставьте **COOKIE_SECURE=true** при работе через HTTPS.
2. Соберите frontend (`npm run build`) или используйте Docker multi-stage build.
3. Запустите единственный процесс `python scripts/serve.py`, задав `BIND_HOST=0.0.0.0` только когда это действительно нужно. Скрипт запрещает сетевой bind без пароля. Для production используйте supervisor/systemd или Docker restart policy.
4. Поставьте HTTPS reverse proxy (например Caddy/Nginx) с поддержкой WebSocket. Закройте прямой доступ к backend извне; expose только proxy.

Docker:

```sh
cp .env.example .env
# Отредактируйте .env, обязательно задайте APP_PASSWORD.
docker compose up --build -d
docker compose logs -f
docker compose down
```

Compose слушает `127.0.0.1:8000`, данные сохраняются в named volume `monitor-data`. `docker compose down` не удаляет volume; не используйте `-v`, если хотите сохранить историю. Docker-путь подготовлен; фактическая сборка контейнера не проверена в этой Windows-среде.

SQLite по умолчанию: `data/monitor.db`. Для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://user:password@host:5432/database` перед первым запуском. Модели совместимы, драйвер включён. Это **не автоматическая миграция существующей SQLite-истории**: перенос данных и будущие изменения схемы требуют отдельной миграции (например Alembic). Скопируйте SQLite при остановленном сервере для резервной копии. Точки графиков и журнал хранятся 90 дней; сводки сеансов и правила — бессрочно.

## Если что-то не работает

- **Нет Python / окно сразу закрывается:** установите Python с PATH и запускайте `Start.cmd` из терминала, чтобы увидеть ошибку.
- **Ошибка установки:** нужен интернет к PyPI, проверьте proxy/VPN. Повторный запуск безопасно повторит установку.
- **Ошибка API Tuya:** перепроверьте регион, Access ID/Secret, связь с аккаунтом, UID, авторизованные API и срок подписки. Ошибка не переключает приложение в демо автоматически.
- **Розетка ON, а показаний нет:** проверьте поддерживаемые `status` и сопоставление. Некоторые модели только переключают питание.
- **Старая страница после изменения кода:** `Rebuild.cmd`, перезапуск backend, Ctrl+F5 в браузере.
- **Вошли, но cookie не сохраняется локально:** при HTTP используйте `COOKIE_SECURE=false`. Для HTTPS — true.
- **Не работает внешний URL:** добавьте его точный origin (с протоколом и портом) в `ALLOWED_ORIGINS` и перезапустите backend.

Пароль защищает приложение целиком, сессия живёт 24 часа, cookie HttpOnly/SameSite=Strict. Нет регистрации, нескольких пользователей и разграничения ролей. Пустой пароль разрешён только для локальной демонстрации. Секреты не хранятся в frontend, SQLite или CSV.

## О проекте

Учебный проект для управления розетками и анализа энергопотребления; не официальный продукт Tuya. Отдельная 3D-презентация не входит в этот репозиторий. Изображение устройства — иллюстрация и не гарантирует поддержку конкретной модели.

GitHub хранит исходный код. Для работы панели и автоматизаций нужно запустить Python-сервер; GitHub Pages не запускает этот backend. Данные деморежима генерируются заново на вашем компьютере.
